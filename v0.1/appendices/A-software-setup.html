Appendix A — Software Setup

Everything in this book runs in R. Most of it needs nothing beyond a handful of CRAN packages, because the point of the book is that you write the samplers yourself. The one exception is Stan, which we use in Chapter 4 and Chapter 10 (Hamiltonian Monte Carlo), and which needs a C++ compiler on your machine. This appendix walks you through the installation in the order that causes the fewest problems, gives you a small model to confirm that Stan works, and tells you what to do if it does not.

If you took the Bayesian Statistics course on this machine, you probably already have everything. Skip to Section A.4 and run the test model; if it passes, you are done.

A.1 R and RStudio

Install R first and RStudio second; RStudio is an editor and needs R to be there already.

  1. R (4.4 or later). Download the installer for your operating system from cran.r-project.org. On macOS, pick the build that matches your processor (Apple silicon or Intel). If you already have R, check its version with R.version.string and upgrade if it is older than 4.4, because several packages we use no longer support older versions.
  2. RStudio. Download RStudio Desktop from posit.co. Any recent version is fine.

Both are free. Quarto, which we use to build this book, ships inside RStudio; you do not need it for the course.

A.2 R packages

The packages below cover the whole book. Copy this block into the R console and run it once. It downloads binaries on macOS and Windows and takes a few minutes; on Linux it compiles from source and takes longer.

install.packages(c(
  "tidyverse",   # data handling and plots
  "bayesrules",  # data sets from Bayes Rules!
  "bayesplot",   # trace plots and other MCMC graphics
  "posterior",   # effective sample size, R-hat, draws objects
  "coda",        # classic MCMC diagnostics
  "mvtnorm",     # multivariate Normal densities and draws
  "patchwork",   # combining ggplot2 figures
  "rstan",       # Stan
  "bgms",        # Bayesian graphical models, Chapters 7-9
  "lars"         # the diabetes data, Chapters 8-9
))

rstan is on CRAN like the others, and on macOS and Windows it installs as a pre-built binary without compiling anything. That is the easy half. The hard half is that using rstan means compiling each Stan model into C++ the first time you run it, and for that your machine needs a C++ toolchain. The next section installs it.

A.3 Installing Stan

rstan is the R interface to Stan (Carpenter et al., 2017). The Stan program you write is translated to C++ and compiled, so you need a compiler that R knows how to call. What that means depends on your operating system.

macOS. Install the Xcode Command Line Tools by opening the Terminal app and running

xcode-select --install

A dialog asks you to confirm; the download is a few gigabytes and takes a while. You do not need the full Xcode application from the App Store. If you already have the tools, the command says so and you can move on.

Windows. Install Rtools from CRAN, choosing the version that matches your R version: Rtools 4.4 for R 4.4.x, Rtools 4.5 for R 4.5.x, and so on. The CRAN download page for Windows lists them under “Rtools”. Accept the default installation location. A mismatch between the Rtools version and the R version is the most common reason that Stan will not compile on Windows, so check R.version.string before you download.

Linux. You need g++ and make, which on Debian and Ubuntu come with the build-essential package, plus the R development headers (r-base-dev). install.packages("rstan") then compiles rstan and its dependencies from source, which takes ten to twenty minutes. The Stan website, mc-stan.org, has distribution-specific notes.

On all three platforms, restart R after installing the toolchain, and confirm that R can see it:

pkgbuild::has_build_tools(debug = TRUE)

The answer should be TRUE. If it is FALSE, the toolchain is not installed or R cannot find it, and no Stan model will compile until that is fixed; on Windows, an Rtools version mismatch shows up here.

Two settings worth putting in every Stan script

library(rstan)
options(mc.cores = parallel::detectCores())   # run the chains in parallel
rstan_options(auto_write = TRUE)              # keep the compiled model on disk

The first line runs one chain per processor core instead of one after the other. The second saves the compiled C++ next to your Stan file so that the same model is not recompiled every time you fit it. Both are the settings Bayes Rules! uses, and every Stan chunk in this book assumes them.

A.4 Checking your installation

Here is the model you will meet again in Chapter 4: the Beta-Binomial. Suppose 14 of 20 students in a seminar say they use a spaced-repetition app, and suppose a \(\text{Beta}(2, 2)\) prior for the proportion \(\pi\) who do. The posterior is \(\text{Beta}(16, 8)\), with mean \(16/24 \approx 0.667\), and that number is what we check against.

Run the following in a fresh R session. The first time you run it, it will take about a minute, and you will see a line saying that the model is being compiled, possibly followed by compiler warnings. The warnings are normal; only an error that stops the run is a problem.

library(rstan)
options(mc.cores = parallel::detectCores())
rstan_options(auto_write = TRUE)

bb_model <- "
data {
  int<lower=0> n;
  int<lower=0, upper=n> y;
}
parameters {
  real<lower=0, upper=1> pi;
}
model {
  pi ~ beta(2, 2);
  y ~ binomial(n, pi);
}
"

fit <- stan(model_code = bb_model, data = list(n = 20, y = 14),
            chains = 4, iter = 2000, seed = 84735)
print(fit)

Success looks like this. print(fit) starts with a header saying “4 chains, each with iter=2000; warmup=1000” and “total post-warmup draws=4000”, followed by a table with a row for pi and a row for lp__. The mean for pi is 0.67 give or take 0.01, Rhat is 1, and n_eff is somewhere in the low thousands. If you see that, Stan compiles and runs on your machine, and you can use every chapter of the book.

Two things that look alarming but are not: rstan may print long compiler warnings about “unused variable” or “deprecated” declarations while compiling, and on macOS the very first compilation can take noticeably longer than a minute. Two things that are actual failures: an error mentioning make, g++, clang, or “compilation failed” means the toolchain is missing or not found, so go back to the previous section; an error mentioning stanc or a line number in the model is a mistake in the Stan code, so check that you copied the model exactly.

A.5 If rstan will not compile

On some machines, most often a managed university laptop or a very new operating system that CRAN’s binaries do not yet target, rstan installs fine but refuses to compile any model, and the error message does not point to a fix. Rather than lose an afternoon, switch to cmdstanr. It is a second R interface to the same Stan, developed by the Stan team, that talks to a separate CmdStan installation instead of compiling inside R’s own toolchain. It is less convenient to install but more robust once it runs.

cmdstanr is not on CRAN. Install it from the Stan team’s R-universe repository, let it repair the toolchain, and then let it download and build CmdStan:

install.packages("cmdstanr",
                 repos = c("https://stan-dev.r-universe.dev", getOption("repos")))
library(cmdstanr)
check_cmdstan_toolchain(fix = TRUE)   # installs what the compiler is missing, if it can
install_cmdstan(cores = 2)            # downloads and builds CmdStan; several minutes
cmdstan_version()                     # a version number means it worked

On Windows, check_cmdstan_toolchain(fix = TRUE) also needs Rtools, so install that first. On macOS it needs the Xcode Command Line Tools, so the previous section still applies; what cmdstanr sidesteps is the integration between the compiler and R’s own build settings, which is where rstan usually fails.

All Stan code in this book is written for rstan, and translating it takes two lines. Where the book writes

fit <- stan(model_code = bb_model, data = bb_data, chains = 4, iter = 2000, seed = 84735)

you instead compile and sample in two steps:

mod <- cmdstan_model(write_stan_file(bb_model))
fit <- mod$sample(data = bb_data, chains = 4, iter_warmup = 1000, iter_sampling = 1000, seed = 84735)

Note that cmdstanr counts warm-up and sampling iterations separately, while rstan’s iter includes warm-up (by default, the first half). Everything after sampling can be the same, because the posterior and bayesplot packages work with both kinds of fit. To get a draws object that the book’s diagnostic code can use:

draws <- posterior::as_draws_array(as.array(fit))   # rstan
draws <- fit$draws()                                # cmdstanr

From here on, posterior::summarise_draws(draws) and bayesplot::mcmc_trace(draws) behave identically. If you use cmdstanr, fit$summary() plays the role of print(fit), and fit$draws(format = "df") gives you the draws as a data frame.

A.6 Reproducibility: seeds and sessions

Every method in this book is a simulation, so running the same code twice gives different numbers unless you fix the random number generator. Two seeds matter.

R’s seed. set.seed() fixes the state of R’s random number generator, so that every rnorm(), runif(), and sample() call that follows is reproducible. The book sets set.seed(84735) at the top of every chapter, a nod to Bayes Rules!. Set it once, at the top of your script, not before every sampler call: re-seeding inside a loop gives you the same “random” numbers again and again.

Stan’s seed. Stan runs outside R and has its own generator, so set.seed() does not reach it. Pass seed = to stan() (or to $sample() in cmdstanr), as the test model above does. With the same seed, the same model, the same data, and the same number of chains, Stan produces the same draws, though not necessarily across different Stan versions or operating systems.

set.seed(84735)
x <- rnorm(3)
set.seed(84735)
identical(x, rnorm(3))
[1] TRUE

Reproducible does not mean correct. A seed makes a bug repeatable, which is useful for finding it, but when you want to know whether a sampler works, run it with several seeds and check that the conclusions do not change. Chapter 4 makes this idea precise.

Finally, when you report a problem or hand in an assignment, include the output of sessionInfo(). It lists your R version, your operating system, and the version of every loaded package, which is usually the first thing anyone helping you will ask for.

sessionInfo()

Setup checklist

  1. R 4.4 or later, and RStudio.
  2. The package block above, run once.
  3. A C++ toolchain: Xcode Command Line Tools (macOS), Rtools matching your R version (Windows), or build-essential (Linux).
  4. The Beta-Binomial test model compiles and reports a posterior mean for pi near 0.67.
  5. If step 4 fails: cmdstanr from the Stan R-universe, check_cmdstan_toolchain(fix = TRUE), install_cmdstan().
  6. Seeds: set.seed() for R, seed = for Stan; sessionInfo() when asking for help.
