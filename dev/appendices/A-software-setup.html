Appendix A — Software Setup

The examples in this book run in R. Packages help with data, plots, and diagnostics, while you implement many of the samplers yourself. Fitting a Stan model also requires a C++ compiler. This appendix explains how to install the software, test a small model, and identify where to look if the test fails.

If you already use R and Stan on this computer, begin with the test in Section A.4. A successful run confirms that this example can compile and sample in your current installation. If a package or compiler is missing, return to the relevant setup step below.

A.1 R and RStudio

Install R first and RStudio second; RStudio is an editor and needs R to be there already.

  1. R. Download a current release from CRAN using the link for your operating system. On Windows, use the Windows installer. On macOS, choose the installer for your processor (Apple silicon or Intel). On Linux, follow CRAN’s instructions for your distribution. If R is already installed, R.version.string reports its version; older installations may need an update to install current packages.
  2. RStudio. Install RStudio Desktop for the same operating system. RStudio provides an editor, console, and tools for managing your R work.

Both are free. Quarto, which we use to build this book, ships inside RStudio; you do not need it for the course.

A.2 R packages

The following packages cover Chapters 1–5 and the installation checks in this appendix. On Linux, complete the compiler setup in Section A.3 before installing R packages from source. Run the installation block once in the R console. Later, use library() to load the packages listed at the start of the chapter you are studying.

install.packages(c(
  "tidyverse",  # data handling and plotting
  "bayesrules", # course data sets
  "patchwork",  # combining plots
  "mvtnorm",    # multivariate Normal densities and draws
  "posterior",  # draws objects, ESS, R-hat, and MCSE
  "bayesplot",  # plots of simulation output
  "rstan",      # fitting Stan models from R
  "knitr",      # displaying tables in the examples
  "pkgbuild"    # checking the compiler setup
))

Packages that these depend on, such as dplyr, tidyr, and scales, are installed automatically. For the later chapters, also install

install.packages(c(
  "lars",     # diabetes data, Chapters 7–9
  "bgms",     # graphical-model examples, Chapters 7–9
  "numDeriv"  # numerical gradient checks, Chapter 10
))

On Windows and macOS, CRAN usually provides precompiled packages for current supported R versions. On Linux, packages are commonly compiled from source. Installing rstan and compiling a Stan model are separate steps: even with a precompiled R package, fitting your own Stan model requires a C++ compiler.

A.3 Installing Stan

rstan is the R interface to Stan (Carpenter et al., 2017). The Stan program you write is translated to C++ and compiled, so you need a compiler that R knows how to call. What that means depends on your operating system.

macOS. Install the Xcode Command Line Tools by opening the Terminal app and running

xcode-select --install

This installs the Command Line Tools, the smaller toolset containing the compiler and other command-line utilities. You do not need the full Xcode application. If the tools are already installed, the command reports this.

Windows. Install Rtools using the version recommended for your installed R version. Check R.version.string first and follow the matching link on the Rtools page. Use the default installation location unless your institution provides different instructions.

Linux. Install a C++ compiler, make, and R’s development files. On Debian and Ubuntu, these are supplied by build-essential and r-base-dev. Other distributions use different package names; follow their R installation instructions. The RStan installation guide links to platform-specific toolchain instructions.

On all three platforms, restart R after installing the toolchain, and confirm that R can see it:

pkgbuild::has_build_tools(debug = TRUE)

A result of TRUE indicates that the build-tools check succeeded. If it returns FALSE, inspect the diagnostic messages and the instructions for your platform before attempting the model below. This check helps locate compiler problems; compiling the actual Stan model is the next test.

Stan settings used in the examples

library(rstan)
rstan_options(auto_write = TRUE)
options(mc.cores = 1)

auto_write = TRUE allows RStan to reuse saved compiled models. mc.cores = 1 runs the chains one after another, as in the setup for Chapter 4. Multiple chains still run; this setting controls how many can run at the same time. On a suitably configured computer, a larger value allows parallel chains.

A.4 Checking your installation

We use a small Beta-Binomial model whose posterior can be checked exactly. Suppose 14 of 20 students in a seminar say they use a spaced-repetition app. With a \(\text{Beta}(2,2)\) prior on the proportion \(\pi\), the posterior is \(\text{Beta}(16,8)\), with mean \(16/24\approx0.667\).

Run this example in a fresh R session after installing the compiler and packages. Compilation may take longer than sampling. The refresh = 0 argument suppresses the sampling progress display.

library(rstan)
rstan_options(auto_write = TRUE)
options(mc.cores = 1)

bb_model <- "
data {
  int<lower=0> n;
  int<lower=0, upper=n> y;
}
parameters {
  real<lower=0, upper=1> pi;
}
model {
  pi ~ beta(2, 2);
  y ~ binomial(n, pi);
}
"
bb_data <- list(n = 20, y = 14)
fit <- stan(model_code = bb_model, data = bb_data,
            chains = 4, iter = 2000, warmup = 1000,
            seed = 84735, refresh = 0)

The following output shows a completed run:

print(fit, pars = "pi", probs = c(0.025, 0.975), digits_summary = 3)
Inference for Stan model: anon_model.
4 chains, each with iter=2000; warmup=1000; thin=1; 
post-warmup draws per chain=1000, total post-warmup draws=4000.

    mean se_mean    sd  2.5% 97.5% n_eff  Rhat
pi 0.671   0.002 0.093 0.474 0.838  1399 1.002

Samples were drawn using NUTS(diag_e) at Fri Oct 30 13:38:20 2026.
For each parameter, n_eff is a crude measure of effective sample size,
and Rhat is the potential scale reduction factor on split chains (at 
convergence, Rhat=1).

The header reports four chains and 4,000 retained draws in total: each chain runs for 2,000 iterations and discards its first 1,000 as warm-up. The estimated mean for pi should be close to the exact value 0.667. The sd column describes posterior uncertainty; se_mean describes Monte Carlo uncertainty in the estimated mean. Different software versions or machines can give somewhat different simulation results.

Completing this example confirms that the installation can compile and sample this model. Examine any warnings as well as the printed estimates. An error mentioning make, g++, clang, or compilation often points to the compiler setup. A Stan syntax error points to the model text. Warnings about the sampled chains require the checks described in Chapter 4; successful compilation alone does not establish accurate inference.

A.5 If rstan will not compile

If the compiler check succeeds but RStan still fails to compile, consult the platform-specific RStan guide using the complete error message. On a managed computer, installation changes may require help from your university’s support service.

An alternative is cmdstanr, another R interface to Stan. It uses a separate CmdStan installation, so it can avoid some RStan-specific compiler-configuration problems. It still needs a working C++ toolchain. The CmdStanR getting-started guide gives the installation steps:

install.packages("cmdstanr",
                 repos = c("https://stan-dev.r-universe.dev", getOption("repos")))
library(cmdstanr)
check_cmdstan_toolchain()
install_cmdstan(cores = 2)
cmdstan_version()

On Windows, check_cmdstan_toolchain(fix = TRUE) can attempt to configure missing toolchain components; this option does not repair macOS or Linux installations. Follow the compiler instructions for your platform first.

To fit the same test model with CmdStanR, use the bb_model and bb_data objects defined above:

mod <- cmdstan_model(write_stan_file(bb_model))
fit_cmdstan <- mod$sample(
  data = bb_data, chains = 4, parallel_chains = 1,
  iter_warmup = 1000, iter_sampling = 1000, seed = 84735)

RStan’s iter = 2000 includes warm-up. CmdStanR specifies the 1,000 warm-up and 1,000 retained iterations separately. Its fitted object also has different methods: for example, fit_cmdstan$summary() gives its summary table.

For the diagnostic workflow in Chapter 4, convert either fitted object to the draws format used by posterior and bayesplot. With RStan:

draws <- posterior::as_draws_array(as.array(fit))

With CmdStanR:

draws <- fit_cmdstan$draws()

Both draws objects can then be used with functions such as posterior::summarise_draws() and bayesplot::mcmc_trace(draws, pars = "pi").

A.6 Reproducibility: seeds and sessions

Examples that generate random draws use seeds so that you can repeat the calculation. R and Stan have separate random number generators.

R’s seed. Run the package setup and any earlier code that defines the data and functions needed for an example. In Chapters 1–5, the simulation chunks set their own seed before drawing random numbers. Rerunning one of these chunks therefore restarts its random sequence. Follow the seed shown in the example; some illustrations deliberately use a different value.

The following two calls produce the same values because we reset the seed between them:

set.seed(84735)
first <- rnorm(3)
set.seed(84735)
second <- rnorm(3)
rbind(first = first, second = second)
            [,1]       [,2]      [,3]
first  0.6672327 -0.1238403 0.7808676
second 0.6672327 -0.1238403 0.7808676
identical(first, second)
[1] TRUE

Resetting a seed at the start of an example is different from resetting it inside a sampler’s iteration loop. Inside the loop, the reset would repeatedly generate the same numbers and change the sampling procedure. The R random-number documentation explains how set.seed() controls the generator.

Stan’s seed. set.seed() does not set Stan’s generator. Supply seed = to stan() or the CmdStanR $sample() method, as in the examples above. Exact reproduction also depends on the model, data, initialization, chain configuration, software, and computing environment; see the Stan reproducibility documentation. Small differences across installations are possible even with the same seed. Compare posterior summaries with their Monte Carlo uncertainty rather than expecting every saved value to match.

A reproducible calculation can still contain an error. When assessing a sampler, also try other seeds and starting values, and use the diagnostics in Chapter 4.

Finally, when you report a problem or hand in an assignment, include the output of sessionInfo(). It lists your R version, your operating system, and the version of every loaded package, which is usually the first thing anyone helping you will ask for.

sessionInfo()

Setup checklist

  1. R and RStudio installed for your operating system.
  2. The packages needed for your chapters installed; the chapter’s setup code loaded.
  3. A working C++ toolchain for Stan: Command Line Tools on macOS, matching Rtools on Windows, or the appropriate compiler and R development packages on Linux.
  4. The Beta-Binomial test model compiles and runs, with an estimated mean near 0.667 and its output and warnings inspected.
  5. Seeds supplied separately for R and Stan; sessionInfo() available when reporting a problem.
